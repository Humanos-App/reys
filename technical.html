The problem

Two documents.
One consent.

In VIA, an organisation publishes an action and its rules. An agent requests a mandate against it, fills in the values and writes the description the person reads. The person approves the description, but only the rules are enforced, and nobody checks that the two agree.

Slips through: slack_send_message() with no channel at all. The guard lets it pass.

This is a real pattern: it appears in actions published on our own development platform. It reads as "only #deploys", but a call that leaves the channel out is never checked. The current Reys misses this one: it gives a stated limit isn't enforced only 0.23. The earlier, Laya-initialised version caught it (0.92). Guarded rules like this are exactly where more real training data is needed.

Four questions

What Reys asks.

A description is faithful when it survives all four questions. Each is yes or no, with a calibrated probability, and each has one precise meaning.

i

A stated limit isn't enforced

The text names a channel, a domain, an amount or a number of uses, and some call the rules allow breaks it.

"email colleagues at acme.com": the rule checks endsWith('@acme.com'), so x@evil.com,ok@acme.com passes.

ii

A change it never mentions

The rules allow a write (sending, editing, creating) that the text doesn't tell the person about.

"Post status updates in #incidents": no tool rule, so every Slack write is open.

iii

A promise the rules never allow

The text says the agent will do something that no allowed call can do. The person approves a permission that doesn't work.

"Book a hotel in Porto": the rule says city == 'Lisbon'.

iv

A deletion it never mentions

The rules allow something destructive (trash, delete, cancel, void) that the text never says.

"Criar eventos na tua agenda": the grant includes delete_event.

Adversarial

Tell it to say no.

The description is written by the agent, so it can't be trusted. It can talk to the reviewer, reassure or instruct. These are three unfaithful mandates with a sentence added to fool the checker. Reys's answers don't move, because nothing about what the rules allow has changed.

How it's built

Made from real tools,
checked by proof.

No hand labelling at scale and no language model deciding what's true. Every training label is a checked counterexample, a real call the rules allow that the text doesn't admit, or its absence.

Tool surfaces326 tools14 real services

Slack, Gmail, GitHub, Stripe, Notion…, each tool labelled read, write or destructive.

Generator26 breaksMinimal pairs

A correct action, then exactly one thing broken: a rule, a value or the text.

Checker0 guessesCounterexample search

Runs the VIA SDK's own rule evaluator over candidate calls to find what slips through.

Round trip2 modelsWrite, then read back

Gemini Flash writes the text; Claude Haiku reads it back. If they disagree, the text is dropped.

Gates≤ +3 ptsNo shortcuts

Text-only and rules-only baselines must not beat "always the common answer".

Training17 minOne H100

A decision model on plain mmBERT-base, trained on 6,330 descriptions × 4 questions (3,374 authorizations, 17 domains), in two languages.

Encoders

Bigger isn't better here.

Same data, same recipe, three encoders. The larger English model is 2.4× slower and loses Portuguese. Starting from Laya's pretraining is a trade, not a win: a little better on the sealed batch, a little worse on real mandates. Reys ships the plain mmBERT-base. The limit is the data, not the encoder.

What's next

An agent asks.
A person checks.

The next test set comes from real tasks. You ask a review agent for something; it requests mandates against published actions, some of them with realistic flaws; the checker answers; a person approves or corrects. It can also play the malicious agent that asks for one thing too many.

Reys

Named after Ricardo Reis, the classicist among Fernando Pessoa's heteronyms. A decision model for the VIA protocol (v0.3, §20: the mandate's description): Laya's decision-model architecture, trained from plain mmBERT-base, the multilingual ModernBERT.
