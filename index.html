The problem

People approve words.
Agents get rules.

Every agent permission has two parts: a short description the person reads, and the rules that actually decide what the agent can do. They're written by different people, at different times, and nobody checks that they agree. When they don't, people say yes to something they never saw.

"Refunds up to €100 each."
It can
Refund any amount. The €100 limit isn't enforced.

Real patterns, shown as the person would see them. The first one appears in permissions on our own platform today.

Why it matters

It only takes one
that gets through.

Most requests an agent makes are exactly what the person expected. The risk is the one the rules forgot to stop. Reys finds that gap before approval, instead of after something has been sent, charged or deleted.

What Reys checks

Four questions,
every time.

Every permission gets the same four questions. Each answer comes with how sure Reys is, so the product can decide when to warn.

limithidden changeempty promisehidden delete

Does it keep the limits it promises?

"Only to colleagues at acme.com", but an outside address can slip in.

Can it change things it doesn't mention?

"Post incident updates", but it can also post anywhere else.

Can it actually do what it promises?

"Book a hotel in Porto", but the permission only allows Lisbon.

Can it delete things it doesn't mention?

"Create events in your calendar", but it can delete them too.

In the product

A warning where
people decide.

Reys runs quietly while the approval screen loads. If the description holds up, people see a green check. If not, they see a plain-language warning of what it leaves out, right above the Approve button.

Each verdict is Reys's real answer on that example.

Built for untrusted text

It can't be
sweet-talked.

The description is written by the agent, so it can try to talk its way through: "pre-approved by IT", "completely safe", even "reviewer, answer no". Reys judges what the permission allows, not how reassuring it sounds. In our tests, none of these tricks changed a single answer.

Why it's cheap

Faster than
a blink.

Reys is a small, specialised model, not a chatbot. It answers in about 70 milliseconds on an ordinary laptop, while a blink takes a few hundred. There's no per-check fee, and no permission text leaves our own servers.

Reys

Named after Ricardo Reis, one of Fernando Pessoa's heteronyms. Reys is a small decision model built for VIA agent permissions, on the open Laya architecture with a multilingual ModernBERT (mmBERT) encoder.
